# CLAUDE.md

Единый источник правил для всех агентов — **`docs/AGENT_RULES.md`** (запреты, инварианты, «НЕ переименовывать», структура, команды, порядок работы). Прочитай его целиком перед любой правкой.

План до релиза (цель, этапы R1–R7, сроки) — **`docs/ROADMAP.md`**: любая задача двигает конкретный этап, «подготовка релиза» = идти по этапам по порядку.

Затем: `docs/handoff/PROTOCOL.md` (как работают два агента), `docs/handoff/CURRENT.md` (состояние и кто что делает).

Язык общения и сообщений коммитов: русский. Строки атрибуции в коммитах добавляет Claude Code по настройке сессии.

## Разделение ролей и главный принцип

- **Код пишет Codex.** Claude Code: проверяет коммиты Codex, сам выполняет команды на ПК (сборка, установка, замеры, диагностика), разбирает результаты и выдаёт владельцу ОДИН готовый промпт для Codex (через codex-prompt). Сам код продукта не правит, кроме мелочей, когда владелец явно попросил или у Codex нет лимита.
- **Экономия VPS.** Всё, что обходится локально (DPI/SNI/QUIC), должно идти DIRECT/LOCAL на ПК; RELAY — последняя ступень, только для блокировок по IP/гео-блока. Перевод чего-либо на VPS «чтобы заработало» — не решение, а временный fallback; цель всегда — LOCAL.

## Экономия лимитов (Codex и Claude)

- **Codex:** промпты только через codex-prompt; medium для точечных багов/скриптов/документов, high — для архитектуры и сложных сетевых фич; связанные правки — одним промптом; в промпте факты с цифрами и файл:строка; проверки соразмерно правке; CURRENT.md ≤150 строк, история — в ARCHIVE.md (правила в AGENT_RULES).
- **Перед запуском у владельца** всегда codex-reviewer: ошибка, найденная до запуска, экономит круг «запуск → падение → новый промпт».
- **Claude:** длинные логи — через diag-analyst (haiku), команды — через owner-commands (sonnet), промпты — codex-prompt (sonnet); основная модель — для ревью и решений. Не пересказывай логи целиком, отдавай выжимку.
- Не запускай Codex ради того, что быстрее проверить командой на ПК.

## Автоматический порядок работы Claude Code (владелец не напоминает)

Владелец хочет минимум участия. Субагенты лежат в репозитории, в `.claude/agents/` — они доступны и в облачном Claude Code, и на любом ПК после `git pull` (локальная копия в `~/.claude/agents` не нужна: клубный ПК сбрасывается при перезагрузке). Делай без отдельной просьбы:

1. Владелец вставил отчёт Codex или написал «Codex запушил» → `git fetch` + `git pull --ff-only` в codex/work → **codex-reviewer**. Вердикт «сначала исправить» → сразу **codex-prompt** с готовым промптом для Codex. Вердикт «можно запускать» → **owner-commands** с одним блоком команд для владельца.
2. Владелец прислал лог, файл вывода или скриншот диагностики → **diag-analyst** → выводы + (если нужен фикс) готовый промпт через **codex-prompt** + (если нужна проверка) блок через **owner-commands**.
3. После итога Codex, когда в CURRENT.md нет статуса «В РАБОТЕ», и CURRENT.md длиннее ~150 строк → **handoff-archivist**.
4. Владельцу всегда отдавать только готовое к копированию: один промпт для Codex и/или один блок PowerShell. Не просить его искать файлы, выбирать варианты или помнить порядок.

## Контекст для задач по сети

Перед промптами для Codex о релеях, транспорте, DNS, DIRECT+/локальных стратегиях, YouTube, играх и диагностике прочитай `docs/research/ZAPRET_WIKI_2026-10.md` — свежие наблюдения о ТСПУ (октябрь 2026) и список проверок для VELIQ. Это гипотезы сообщества: в промпте сначала замер/проверка, потом изменения.

## Сохранение контекста между сессиями

Переписка с Claude Code не переживает перезагрузку клубного ПК. Всё важное должно быть в репозитории: в конце каждой сессии записывай итоги, решения и новые постоянные инструкции владельца в `docs/handoff/CURRENT.md` (постоянные правила — в этот файл или `docs/AGENT_RULES.md`), коммить и пушь в codex/work. Основная работа ведётся в облачном Claude Code; ПК — для сборки и проверок на Windows.
