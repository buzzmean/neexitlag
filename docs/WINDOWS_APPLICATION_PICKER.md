# Добавление приложения в Windows

В разделе «Приложения» нажмите «Добавить приложение». Откроется список запущенных пользовательских приложений: название, exe, полный путь, PID и число процессов. Один executable path показан один раз; одинаковые имена exe из разных каталогов остаются отдельными строками. Список изначально отсортирован по имени; поиск учитывает название, exe, путь и показанные PID. «Обновить» заново запрашивает сервис. Двойной клик по строке или «Добавить» создаёт обычный custom AUTO profile с полным путём, не с PID.

Если приложение не запущено, выберите «Выбрать файл вручную». Отмена file picker ничего не добавляет. Перед сохранением GUI перечитывает актуальные profiles под своим mutation gate; повторный полный путь не создаёт второй профиль и показывает «Это приложение уже добавлено». После успешного `profile.set` строка добавляется сразу, без ожидания следующего polling tick или перезапуска GUI.

GUI остаётся `asInvoker`. Существующий authenticated IPC `processes` расширен опциональным запросом:

```json
{"applications":true,"limit":128}
```

Ответ: `{applications:[{name,path,pid,creation_time,pids,process_count}],truncated}`. Старые nil/`{executables:[...]}` запросы сохраняют массив ProcessIdentity и прежнюю фильтрацию. Нельзя смешивать `applications` и `executables`; limit — 1–128 (отсутствие/0 означает 128). Новый список использует тот же ProcessDiscovery и `PROCESS_QUERY_LIMITED_INFORMATION`; GUI не сканирует процессы самостоятельно. Session 0, системные host-процессы, VELIQ/service, отсутствующие creation time и невалидные DOS executable paths пропускаются. Список не определяет владельца Windows account: он показывает доступные интерактивные сессии, а не заявляет атрибуцию только текущему пользователю.

Ограничения: не более 4096 входных process identities, 128 приложений, 16 показанных PID на приложение и 48KB JSON строк до IPC envelope. Полное число процессов сохраняется для просмотренных identities; при превышении лимита сканирования/числа строк/размера ответа GUI явно сообщает о неполном списке. UNC/device paths в автоматический список не входят; ручной выбор остаётся доступен. Для старого сервиса, не поддерживающего новый запрос, окно показывает ошибку, но ручной выбор продолжает работать.

Название из FileDescription и иконка — необязательные presentation metadata из локального exe на fixed/removable drive, читаемые в background один раз на строку при refresh. Никакого запуска exe, elevation, чтения памяти, injection, извлечения publisher/signature или сетевой загрузки иконок. Ошибка metadata оставляет имя exe и пустую иконку. Завершение процесса между refresh и выбором допустимо: профиль идентифицирует существующий файл по полному пути и пригодится при следующем запуске.
