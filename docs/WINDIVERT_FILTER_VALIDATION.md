# Проверка фильтров WinDivert 2.2.2

## Отказ e3dc65c

Причина — `and not ((outbound ...` в исключении частного iSCSI. Грамматика
WinDivert 2.2.2 разрешает `not` / `!` перед отдельным тестом, но не перед группой.
Для точного фильтра владельца (TCP reflection port 62841, длина 574 байта)
`WinDivertHelperCompileFilter` сообщает `Filter expression parse error`,
нулевая позиция **117**, первая скобка после `not`. Даже `not (outbound)`
отклоняется в позиции 4. Это не проблема драйвера, подписи или прав.

Фильтр переписан по правилу де Моргана (553 байта для порта 62841). Сохранены
направления и RFC1918-адрес **сервера**: исходящий TCP к private:3260 и входящий
ответ private:3260 исключены ещё в ядре. Публичный TCP:3260, а также защищённый
HTTPS с локальным портом 3260 не исключаются. UDP/игровые/браузерные решения не менялись.

У 2.2.2 есть отдельные пределы сложности: внутренний бюджет рекурсивного разбора
1024 и предел массива 256 инструкций (драйвер требует длину меньше 256).
Они не объясняют этот отказ. Регрессии проверяют длинный валидный текст
(4096 пробелов + `tcp`), отклонение 300 разных условий и 600 вложенных скобок.
В последнем случае API закреплённой DLL возвращает `parse error` в позиции 341:
парсер перезаписывает внутреннюю причину глубины при выходе из рекурсии.
Версия, SHA256 DLL/драйвера и зависимости проекта не изменены.

## Обязательный барьер сборки

`build-e2e.ps1` до сборки службы:

1. Проверяет по Go AST, что все production-вызовы открытия фильтров входят
   в тестируемый список и используют правильный слой.
2. Собирает `capture-acceptance.exe` и запускает `test-windivert-filters.ps1`.
3. Загружает **настоящий закреплённый DLL** и компилирует/сериализует все семь
   фильтров: FLOW, UDP NETWORK, SOCKET, IPv6 NETWORK, REFLECT, game UDP replies,
   TCP NETWORK. Проверяются TCP-порты 1/3260/50165/62841/65535 и оба fixture-режима.
4. Через настоящий `WinDivertHelperEvalFilter` проверяет iSCSI в обе стороны,
   границы трёх частных диапазонов и отсутствие обхода публичного HTTPS.
5. Требует PASS каждого теста; SKIP, отсутствие DLL, неверный SHA256, ошибка
   компилятора или отсутствие теста прекращают сборку. Если каталога DLL нет,
   скачивается прежний официальный pinned 2.2.2; существующий каталог не перезаписывается.

Тест не вызывает `WinDivertOpen`, не устанавливает/запускает драйвер и не требует
администратора. Verify и Game UDP Windows CI запускают ту же проверку до сборок
и загрузки артефактов. Сборка Setup также проходит этот барьер.

В самой службе каждый `openHandle` дополнительно вызывает компилятор **до**
драйвера; ошибка включает `WINDIVERT_FILTER_COMPILE_FAILED`, слой, offset, length,
сообщение DLL и фильтр. Поэтому следующий ошибочный фильтр не скрывается за
общим `The parameter is incorrect`.

## Что проверено в среде разработки

Настоящий официальный x64 DLL с прежним SHA256 исполнен под Wine 10 в отдельном
временном каталоге Linux: все 70 сочетаний фильтр/порт/fixture, проверки iSCSI,
точный исходный отказ и ограничения сложности PASS. Это **не** Windows kernel /
WinDivertOpen / матч PUBG / Internet PASS. Windows-фикстура и барьер включены
в сборку, окончательный запуск захвата проверяет владелец на своём ПК.
