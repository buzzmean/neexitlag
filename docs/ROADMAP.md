# ROADMAP — план до клубного релиза VELIQ

Единый план для владельца, Codex и Claude Code. Короткий: статус меняется одной строкой.
Детали работ — в docs/handoff/CURRENT.md и профильных docs. Этапы здесь называются R1–R7
(не путать с фазами измерений M1–M5 в CURRENT.md).

## Цель релиза (Definition of Done)

Клуб в Ставрополе, ~40 ПК, бездисковая система Langame (откат при перезагрузке).

1. Один установщик `VELIQ-Setup.exe`, один клубный код на все ПК, установка в образ без ручных шагов на каждом ПК.
2. Гость включает ПК → VELIQ уже работает: без диалогов, перезагрузок, перезапуска браузеров, ручных добавлений.
3. Заблокированные сайты и сервисы работают: YouTube, Discord, Telegram, ChatGPT, Claude, Instagram и т.п.; обычные сайты (VK, Яндекс) — напрямую без задержек.
4. Игры: PUBG (обход UDP без VPS), Riot/Valorant (Vanguard), FACEIT — запускаются и играются, античиты не ругаются.
5. Экономия: всё, что обходится локально (DPI/SNI/QUIC), идёт DIRECT/LOCAL на ПК; через VPS — только блокировки по IP/гео-блок. Цель — трафик VPS на клуб укладывается в тариф (Hostkey 3 ТБ/мес) с запасом.
6. Отказоустойчивость: основной + запасной relay, автоматическое переключение; падение VELIQ не ломает интернет ПК.
7. Безопасность: засвеченные и тестовые коды отозваны, финальный клубный код выпущен и нигде не опубликован; сертификаты продлеваются автоматически.

## Ограничения по срокам

- **12.11.2026** — кончается оплата 2.56.177.4 (там активация). До этой даты R3 должен быть решён, иначе новые ПК не активируются.
- **7.11.2026** — турнир в клубе: в эти дни ничего экспериментального на клубные ПК не выкатывать.

## Порядок работ сейчас

1. R1: починить LOCAL (главное для экономии и масштаба на 40 ПК).
2. R3: решение по серверам до 12.11.
3. R4 → R5 → R6 → R7.
R2 проверяется владельцем в реальных матчах параллельно, когда есть время.

## Правила для агентов

- Публичная версия плана — страница сайта `website/roadmap.html` (данные в `design/tools/build-site.py`, блок ROADMAP). Меняешь статус этапа здесь — обнови и сайт (без адресов и расположения серверов, кодов, внутренних сроков, названий клубов, игр и сторонних систем, без «образа» и непроверенных обещаний — правила в `brand/copy.md`), запусти `python3 design/tools/build-site.py`.

- Каждая задача должна двигать конкретный этап R1–R7; в итоге задачи — какой этап и что изменилось.
- Статус в таблице обновляет тот, кто закрыл критерий, по факту проверки у владельца (а не по тестам под Wine/CI).
- «Подготовка релиза» = идти по этапам по порядку; не начинать R4–R7, пока R1 не готов, без решения владельца.
