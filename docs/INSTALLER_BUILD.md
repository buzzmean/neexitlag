# VELIQ-Setup.exe: сборка и границы первого пакета (B1)

Реализация: `installer/setup.iss`, `build.ps1`, `install-package.ps1`,
`package-contract.ps1`; workflow `installer.yml`. Пользователю не нужны Git, Go,
SDK или команды. Администратор один раз подтверждает UAC установщика (на UAC-off
этого запроса нет). Перезапуск Windows/браузеров не запрашивается и не делается.

Внутри офлайн EXE: self-contained GUI и alias, служба, неизменённый WinDivert
2.2.2, pins.json и лицензия, публичный CA с DER SHA256, публичные адреса, SHA256
каждого payload-файла, точный source commit. Нет identity/device key, CA private
key, admin token, кода активации, SSH или provisioning. Встроенный Windows
PowerShell 5.1 используется скрытым ограниченным setup helper, без консоли и
ручного ввода команд. Это первый этап; перенос helper в подписанный native EXE
до широкого коммерческого выпуска остаётся задачей усиления упаковки.

Сборка требует уже собранные `bin/windows-e2e`, `bin/release`, `.e2e/windivert`
и отдельный каталог **только** с публичным `ca.pem`. Компилятор Inno Setup 6.4.3
(одобрен форматом задачи B1) нужен только на машине сборки; версия и Authenticode
проверяются. Новых runtime/Go/NuGet зависимостей не добавлено. Build формирует
SHA256SUMS. Подлинность скачанного unsigned Setup один SHA256 рядом с ним не
гарантирует: нужен доверенный канал хеша или подпись владельца.

Workflow на одноразовом Windows runner собирает/компилирует Setup. Если переменные
репозитория VELIQ_PUBLIC_CA_PEM / VELIQ_CONTROL_PLANE_URL / VELIQ_PROBE_TARGET
не заданы, строится **не распространяемая** fixture: install helper откажет её
устанавливать, артефакт не публикуется. Публичные production значения задаёт
только владелец. С заданным публичным trust один artifact хранится 3 дня;
публикация в GitHub Releases и подпись — отдельное разрешение владельца.

## Обычный пользователь / обновление

Запускает Setup, устанавливает, вводит код в существующем экране GUI. До активации
capture/PAC не включаются. Setup закрывает только свой GUI через same-user pipe
(новый сигнал 2); чужие процессы и браузеры не трогает. Обновление использует
транзакции update-service и install-desktop; owner SID, identity, профили, SCM,
ProgramData и IPC сохраняются. При ошибке соответствующего компонента работает
его rollback; совместимое промежуточное сочетание версий GUI/service после отказа
другого компонента возможно и явно не называется общей атомарной установкой.
Повтор Setup восстанавливает оставшуюся часть; не удалять state для «лечения».

Поддерживается повышение под **тем же SID**, включая UAC-off full-admin. Если
пользователь вводит credentials другого администратора, Setup откажет, не
назначая identity чужому SID. Silent от SYSTEM без интерактивного владельца
пока не поддерживается; клубный администратор запускает под SID будущего владельца.

Удаление в «Установленные приложения»: остановка GUI/SCM/watchdog, exact-owned
PAC cleanup, удаление только известных GUI файлов с marker/hash и ярлыка;
конфигурация, identity и отчёты сохраняются. Изменённые/чужие файлы не удаляются.
Ошибка cleanup останавливает uninstall до удаления setup payload. Бинарники
драйвера не подменяются; Windows может сохранять загруженный драйвер до reboot,
но сеть/политики и SCM уже должны быть освобождены.

## Клуб / freeze

Чистый образ ставится ActivationOnly, без identity. Тихий запуск администратора:
`VELIQ-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLUBCODEFILE="путь"`.
Файл с обычным длинным club-кодом доступен только владельцу/SYSTEM/Administrators,
не reparse, <=256 байт. Значение не попадает в аргументы/логи; setup вызывает
stage-club-activation с `stage_for_boot=true`. На этом boot enrollment не делается.
Администратор удаляет исходный файл и фиксирует образ; шифрованный staged code
и служба остаются в образе. После boot каждый ПК получает собственный новый ключ
и тот же machine slot после freeze. Не копировать уже активированный образ.
Сохранение кода в защищённом образе не делает его недоступным локальному admin;
для клуба лимит/отзыв остаются на сервере. Интерактивное staging существующим
скриптом остаётся для администратора, обычный игрок вводит код только в GUI.

## Подпись / выпуск — решение владельца

- Без подписи: SmartScreen/антивирус может блокировать Setup, service или WinDivert.
  Исключение допускается только владельцем на точно проверенный hash/путь; сборка
  не выключает защиту, пользователь не получает совет выключить антивирус.
- Платная подпись code-signing: выбрать провайдера и условия (обычно несколько
  сотен USD/год плюс возможная цена аппаратного/cloud signer; точную цену запросить).
  Подписывать GUI/service/Setup/uninstaller и timestamp; секрет signing не в Git.
- WinDivert SYS остаётся с upstream подписью и хешем; наша подпись EXE не заменяет
  kernel signing. Отдельный WFP-драйвер потребует другого процесса подписи.

Локально проверены Python-контракты и синтаксис PowerShell, WPF cross-build.
Реальная сборка ISCC, установка/обновление/удаление, same-owner UAC, staging/freeze,
SmartScreen и запуск Setup на Windows **не подтверждены**. Не раздавать клубу до
одноразовой VM/ПК проверки; CI без шагов/квот не считать проверкой установщика.
