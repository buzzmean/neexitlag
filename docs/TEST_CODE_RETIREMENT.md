# Удаление временного режима активации перед релизом

Статус: чек-лист, **ничего не отозвано и runtime пока не удалён**.
Короткий известный код предназначен только для текущего теста владельца.
В production release его создавать/принимать нельзя.

1. Администратор сначала переводит тестовый ПК на обычный club/personal код и
   проверяет его новую привязку. Сохраняет резервные копии и read-only список мест.
2. Только после отдельного решения владельца отзываются тестовые коды:
   **`revoke-tests` отзывает также ВСЕ привязанные к ним устройства**, публикует
   revocations и разрывает их доступ. Это разрушительное действие, не проверка
   доступности и не часть install/update/runbook smoke test. В этом документе
   команда намеренно не дана в исполняемом блоке.
3. Удалить исключение `temporaryTestCodeHash` из `core/enrollment/code.go`,
   runtime `core/enrollment/test_code.go`; заменить тест принятия короткого значения
   регрессией, что любой такой ввод отклоняется. Обычный криптографический формат
   и hash-only хранение не менять.
4. Убрать `create-test`, `revoke-tests`, флаг `--value` и их подсказки из
   `tools/codes/main.go`, `test_operation.go`; удалить/заменить соответствующие
   тесты запрета старых команд.
5. Убрать admin routes `/api/v1/codes/test`, `/api/v1/codes/revoke-tests` из
   `services/control-plane/codes_api.go`, runtime создания/массового отзыва из
   `codes_temporary.go`; тесты заменить проверкой недоступности старого API,
   обычных club/personal и отказа активации исторического отозванного тестового кода.
6. **Сохранить** `migrations/003_temporary_test_codes.sql`, schema history,
   исторические rows kind=test, хеши, аудит, nonce/replay, revocation и config
   version. Не DROP, не TRUNCATE, не pg_restore старого security state. Миграция
   должна работать и на новой БД, и при update схемы 3. Чтение исторических строк
   совместимо; создание новых kind=test запрещается приложением.
7. Убрать рабочие инструкции создания короткого кода из active docs и packaging.
   Исторические отчёты сохранить, пометить устаревшими. Не вкладывать
   какой-либо код активации в публичный Setup, workflow, fixture или логи.
8. Прогнать enrollment/control-plane/CLI race-тесты с PostgreSQL (включая схему3),
   test-code rejection, revoked devices и slot reuse после freeze, Linux/Windows
   сборки и GUI. В изолированной БД проверить старый test row: остаётся отозванным,
   обычные клиенты работают; предыдущие production binary hashes не менять.
9. Отдельно проверить release payload/CLI help/API и выполнить поиск по
   `temporaryTest`, `create-test`, `revoke-tests`, `/codes/test`. Любое оставшееся
   совпадение классифицировать: миграция/история/негативный тест либо ошибка релиза.

Владелец решает дату отключения и выдачу обычного кода тестовому ПК. Выполняющий
чек-лист не получает разрешения на production revoke/deploy из самого документа.
