# Исследование wiki2.zapret.moe: что известно о ТСПУ и обходах (октябрь 2026) и что это значит для VELIQ

Источник: wiki2.zapret.moe (≈60 из ~300 статей: Zapret 2, «DPI и ТСПУ», игры, DNS, Telegram, Discord, YouTube, диагностика). Это материалы сообщества: цифры — наблюдения, у операторов и регионов отличаются и меняются. Составлено 24.10.2026. Использовать как контекст при подготовке задач по сети, релеям, DNS, DIRECT+ и играм. Выводы о VELIQ — гипотезы для проверки, а не доказанные факты.

## Факты о блокировках

1. **«Три условия» (с июня 2026).** Блок только при совпадении всех: (1) IP в подсети/AS хостинга (Selectel, Яндекс Облако, Cloud.ru, Beget, Leaseweb, Hetzner, Cloudflare, AWS, Fastly); (2) TLS-отпечаток Chrome/Safari/iOS (Firefox, Edge не попадают); (3) >3 параллельных TLS к одному SNI за 60 с с интервалом < ~20–400 мс (порог менялся). Наказание: все TLS к узлу «заморожены» 120 с (TCP открыт, данных нет). Нарушить любое одно условие достаточно.
2. **«16 КБ»:** к облачным подсетям соединение замирает после 16–20 КБ; внутри подсети — белый список SNI.
3. **UDP/QUIC:** ТСПУ часто молча дропает UDP к «подозрительным» адресам. QUIC Initial расшифровывается из публичных данных — SNI и ALPN видны DPI.
4. **DNS:** с августа UDP/53 к 8.8.8.8, 8.8.4.4, 1.1.1.1, 1.0.0.1 перехватывается (DNAT на резолверы НСДИ 195.208.4.1/5.1), заблокированные домены → NXDOMAIN с флагом `aa`. DoH режется по SNI (dns.google, cloudflare-dns.com и др.). 8.8.8.8 по TCP (443/853/53) блокировался с 3 июля, 8.8.4.4 работал. Работают: TCP/53, DoT/DoQ по прямому IP, DNSCrypt, DNS внутри туннеля (надёжнее всего). Проверка подмены — на DNSSEC-подписанном заблокированном домене (подмена → SERVFAIL).
5. **YouTube/GGC:** с 17.10.2026 у ТТК видео с кэшей Google в сети провайдера (`188.43.61.0/24, 188.43.64.0/23, 188.43.66.0/23, 188.43.68.0/23, 188.43.87.0/24, 188.43.126.0/24, 188.43.127.0/24`, AS20485) падает до 144p. Плеер сначала ждёт QUIC (UDP 443) несколько секунд, затем TCP. Узлы видео выбирает страница youtube.com по IP клиента, а не DNS: маршрут `*.youtube.com` через прокси меняет набор узлов. Наблюдался фильтр по SNI `googlevideo.com`, чувствительный к регистру.
6. **JA4:** блокировался отпечаток Chrome 134 (`t13d1516h2_8daaf6152771_d8a2da3f94cd`), задевая FakeTLS MTProto. ClientHello свежего Chrome 1,7–2,1 КБ (`X25519MLKEM768`), делится на 2 пакета; SNI на стыке или во втором пакете в 22 из 47 соединений.
7. **Поведенческие признаки DPI:** отношение вход/выход трафика, ровный поток без пауз, многочасовые соединения, параллелизм к одному SNI; ML после ~16 КБ (размеры, тайминги, энтропия). Голый Go `crypto/tls` узнаваем по отпечатку; пустой SNI на 443 — признак.
8. **Обнаружение VPN приложениями** (MAX и др. проверяют VPN и внешний IP). Если вход и выход VPS — один IP, утечка выдаёт вход. Защита: два IP — клиенты на X, весь исходящий трафик с Y.
9. **Белые списки и регулирование:** адреса компаний в списке ЦМУ ССОП пропускают VPN-протоколы, зарубежные серверы защиты не имеют; обсуждается платный зарубежный мобильный трафик сверх 50 ГБ (только 5G); цель РКН — «эффективность ограничения VPN» 92% к 2030.

## Приёмы обхода (Zapret 2), полезные для DIRECT+

- **circular** (автопереключение стратегий по хосту): неудача TCP — 3 ретрансмиссии до rseq 32768, или RST с rseq ≤ 4096, или HTTP-редирект DPI; неудача UDP — ≥4 исходящих при ≤1 входящем; `fails=3`, сброс счётчика через `time=60` с; состояние по домену (`nld=2`); `final` останавливает перебор.
- **Обработка только начала соединения:** `out-range=-d10` (первые 10 пакетов с данными); не трогать пустые ACK; cutoff после решения.
- **Fooling для fake обязателен** (иначе сервер примет фейк и соединение порвётся): `md5sig` — универсальный; `ts` на Windows не работает без включённых TCP timestamps (по умолчанию выключены: `netsh interface tcp set global timestamps=enabled`); `badsum`/`datanoack` гибнут в NAT домашнего роутера; TTL/autottl зависит от маршрута.
- **Методы:** fake (blob, `tls_mod=rnd,rndsni,sni=`, repeats до ~11), multisplit (pos `midsld`, `sniext+1`, seqovl), multidisorder (seqovl ломает Windows-серверы), fakedsplit/fakeddisorder, hostfakesplit, oob (`urp=midsld`), syndata, tcpseg; wssize замедляет все соединения — крайний случай.
- **Фейк от разрешённого домена** снимал «ковровый» блок на подсетях Cloudflare.
- **Исключения обязательны:** незаблокированные (особенно RU) ресурсы не дурить — фейки их ломают. Порядок профилей: первый подходящий выигрывает.
- **Проверка честная:** только новым соединением (F5 переиспользует keep-alive, ТСПУ помнит помеченные соединения), в целевом приложении, весь сайт с CDN, после полного выхода приложения из трея. Если входящих пакетов 0 — это блок по IP/маршруту, DPI-обход не поможет.

## Сервисы и игры

- **Discord:** `updates.discord.com` — multisplit/multidisorder на первых ~10 пакетах; `discord.media` и голос (STUN) — fake; QUIC у Discord в РФ почти не используется; AdGuard ломает голос.
- **Telegram:** проверять TCP 443 к адресам DC (`149.154.174.100`, `149.154.170.100`, `149.154.167.220`, `149.154.167.99`), а не пинг; звонки только UDP.
- **Steam:** вход — `*.steamserver.net` TCP 27020/27021/27024/443 (AS32590); магазин — Akamai и Fastly (`steamstatic.com` целиком); Valve: TCP/UDP 27015–27050, игры UDP 27000–27250, P2P/голос UDP 3478, 4379, 4380, 27014–27030.
- **Игры в целом:** сначала пробить TCP, потом UDP; игровой UDP распознаётся как `unknown` — нужен `payload=all`; для UDP — fake с QUIC-блобом, autottl, repeats≈10. Battlefield 6: TCP 80, 443, 2053, 2083, 2087, 2096, 8443; UDP 443, 19294–19344, 50000–50100.
- **Конфликты на ПК:** два приложения с WinDivert (например, mitmproxy) мешают друг другу; VPN, системный прокси, расширения браузера (SaveFrom и т. п.), Яндекс Браузер (подменяет DNS) ломают диагностику.

## Диагностика (инструменты сообщества)

DPI Detector (классификатор: `SYN DROP`, `TLS RST`, `TLS MITM`, тест «16–20 КБ», подмена DNS), dpi-checkers (тест TCP 16–20 КБ, «сибирский» тест частоты, поиск белых SNI), rkn-block-checker (послойно DNS→TCP→TLS→HTTP с контрольными сайтами), cheburcheck (картина из других сетей), ByeByeVPN (насколько свой сервер похож на VPN снаружи — только свои серверы). Перед тестами отключать любой обход.

## Что это значит для VELIQ (гипотезы → проверить, по важности)

1. **Релей узнаваем по первому пакету.** Транспорт — QUIC/UDP, в QUIC Initial открыт ALPN `neexitlag/1`, `/2`, `/3` (`core/transport/tls.go`, `core/protocol`). Плюс QUIC дропают. Нужны: нейтральный ALPN (например, `h3`) — только в новой версии протокола с совместимостью (ALPN `neexitlag/*` в списке «НЕ переименовывать»); запасной транспорт TCP+TLS, похожий на обычный HTTPS. Проверить, какой SNI уходит (пустой SNI — признак).
2. **Проверить VPS снаружи и с сети клуба:** dpi-checkers (16–20 КБ, «сибирский»), ByeByeVPN. Пул до 8 сессий к одному релею может срабатывать на «>3 параллельных за 60 с» — замерить.
3. **DNS для приложений:** инвариант «DNS/53 не уходит в relay» + подмена NXDOMAIN → приложения, маршрутизируемые по IP, не получат адрес. Нужен резолвер в службе: DoT/DoQ по IP или запрос через релей (для браузера частично есть: `BROWSER_DNS_ROUTING`, `GOOGLEVIDEO_DNS_RECOVERY`).
4. **DIRECT+:** стратегии каталога с fooling `ts` на Windows без timestamps не срабатывают (код пропускает с `TIMESTAMP_OPTION_REQUIRED`) → заменить на `md5sig` или включать timestamps при установке. Перенять: переключение стратегии по хосту с детектором неудачи (как circular), обработку только первых пакетов, сборку ClientHello из двух пакетов.
5. **Два IP на VPS** (вход/выход).
6. **YouTube:** для доменов через релей дропать QUIC, чтобы плеер не ждал; учитывать, что видео пойдёт с узлов по IP VPS (трафик релея).
7. **Диагностика в программе:** показывать этап обрыва (нет ответа на SYN, сброс на рукопожатии, заморозка после N КБ, подмена DNS).
8. **Каталог игр:** порты Steam/Valve, правило «сначала TCP, потом UDP с payload=all», наборы для Battlefield 6.
